# Separate season start from roster draft start

Source: [issue #1](https://github.com/Rickcern44/swan-league/issues/1). Status: proposed; implementation requires approval.

## Problem

Finishing Setup already leaves a season in `Setup`, but the only start operation requires a draft deadline and opens the roster draft as it makes the season `Live`. A commissioner cannot run a live season with the draft unopened, then open it later.

## Required behavior and decisions

1. Preserve blank season creation and the existing Setup review/finish readiness checks. A season starts only after completed, currently ready Setup and authorization by an active Commissioner membership of that season. Starting without a draft deadline makes it `Live` with `RosterDraftDeadline = null`; it does not create, open, or close any roster. Starting with a valid deadline remains one commissioner action that makes the season `Live` and opens the draft immediately. Repeating either start is rejected without changes.
2. The commissioner may open the draft **manually at any later time** while the selected season is `Live` and its deadline is null. The commissioner enters a closing deadline, confirms, and the successful request opens the draft immediately. “Later date” means the date on which the commissioner takes this action; scheduling an automatic future opening is outside scope. The deadline is still required when opening a draft, is entered as an Eastern wall-clock time, and must resolve unambiguously to an instant strictly after server time and no more than 366 days away. Keep existing skipped/repeated daylight-saving-time and year validation. The server stores the resolved instant. A non-null deadline can never be replaced by this action, including after expiry; no reopen or extension flow is introduced.
3. `Live` plus null deadline means **not yet opened**; `Live` plus future deadline means **open**; `Live` plus expired deadline means **closed**. `Setup` and `Completed` never have an open draft. Server time decides the boundary (`now < deadline`). Existing locked rosters remain locked. Coaches cannot save or lock while unopened or closed; commissioner roster corrections retain their existing authority and behavior.
4. Make the two choices explicit on Setup review: “Start season” and “Start season and open draft.” Only the latter requires a closing deadline. Both show the consequence in confirmation text. After a season-only start, refresh access and direct the commissioner to the Draft page, which shows “not yet opened” and the deadline form/action. After either start, show the resulting state. The Draft page shows the form only to the authorized commissioner while unopened; when open or closed it displays the existing deadline/status without offering another start. The coach roster page shows “draft not yet open” for a live season with null deadline, not “draft closed” or an assertion that the roster is incomplete because a deadline passed. Keep existing roster details visible where applicable.
5. Retain `POST /api/admin/seasons/setup/activate` for both start choices: absent/null `rosterDraftDeadlineEastern` starts without the draft; a supplied valid value opens it atomically with season activation. A supplied blank or invalid value remains 400. Add a commissioner draft start operation, for example `POST /api/commissioner/roster-draft/start` with required `seasonId` and `rosterDraftDeadlineEastern`. It returns the refreshed commissioner draft read model. The `seasonId` must match the selected newest live season so a stale page cannot open another season's draft. Keep the existing response deadline nullable and the commissioner GET/corrections contracts compatible.
6. Record one `season.activated` audit event for season activation, including whether the draft opened and its deadline if supplied. Record a distinct `roster-draft.started` event for a later opening, including actor, season, resolved UTC deadline, and Eastern input. Persist each transition and audit record in one transaction; rejected requests write neither. Do not expose credentials or private roster data in audit details.

## Failure handling

Anonymous callers receive 401; signed-in callers without the active Commissioner membership of the target season receive 403. A missing target season receives 404. Missing/blank/malformed, nonexistent or ambiguous Eastern times, past/equal deadlines, and deadlines beyond 366 days receive 400 for draft opening. Starting a season before Setup is finished or ready, opening while the season is not `Live`, opening an already opened/expired draft, or repeating an activation receives 409 with a stable code and readable message. A stale `seasonId` receives 409 and leaves the current season untouched. Serialize competing start requests on the season row so only one transition and audit record can commit. UI retains entered data on an error and refreshes state after a conflict.

## Non-goals

No scheduled opening, notification, reminder, draft-order system, deadline edit/extension, reopen, automatic roster assignment, new season state, or change to weekly picks. Do not change commissioner correction rights. Existing live seasons with null deadlines also appear “not yet opened” and are eligible for this manual action if they are the selected live season; this follows the current nullable field and avoids an unrequested migration.

## Executable acceptance checks

Write a failing test before each changed behavior, then make it pass.

- Core: completed/ready Setup can activate with null deadline; `RosterDraftOpen` is false. Activation with a valid deadline still opens immediately. A live/null season opens only once with a valid future deadline; Setup, Completed, expired, duplicate, and invalid-time attempts leave state and deadline unchanged. At exactly the deadline it is closed.
- Service/API: with a completed ready Setup and active commissioner, `POST /setup/activate` with `{}` returns `Live` and null deadline; the same endpoint with a valid Eastern deadline returns `Live` and an open draft. The later-start endpoint turns a matching live/null season open and returns its deadline. Assert 401/403/404/400/409 cases above, unchanged persisted state, one appropriate audit event per successful transition, and single-winner behavior for concurrent requests.
- UI: component tests cover both Setup choices, confirmation and errors, the commissioner unopened/open/closed views, and the coach unopened message. Existing immediate-start tests continue to pass.
- E2E: on a running Aspire stack with a dedicated test database, a commissioner starts a season without a draft; a coach sees it unopened and cannot save/lock; the commissioner opens it later with a valid deadline; the coach can save/lock until the deadline; after the deadline coach writes fail. Also exercise immediate start and an unauthorized or stale start. Use the cleanup commands and cautions in `README.md` and `src/Swan.Web/e2e/roster-draft.spec.ts`.
- Required checks before implementation commits: `dotnet format Swan.slnx`, `dotnet format Swan.slnx --verify-no-changes`, `dotnet test Swan.slnx`; for UI changes, `npm run format`, `npm run format:check`, `npm run lint`, `npm test`, and `npm run test:e2e` in `src/Swan.Web` under the dedicated stack. Report each actual result.

- State and deadline: `src/Swan.Core/League/League.cs` (`StartRosterDraft`, `RosterDraftOpen`); `src/Swan.Core/Common/EasternTime.cs`.
- Activation, readiness, audit, and row locking: `src/Swan.Services/League/SeasonSetupService.cs` (`ActivateSeasonAsync`, `InSetupAsync`); `src/Swan.Api/Endpoints/Admin/SeasonEndpoints.cs`.
- Commissioner authorization/read model: `src/Swan.Services/Picks/RosterDraftService.cs` (`CommissionedSeasonAsync`, `CommissionerDraft`); `src/Swan.Api/Endpoints/Coach/CommissionerRosterEndpoints.cs`. Coach writes already consult `RosterDraftOpen`.
- Screens and tests: `src/Swan.Web/src/SeasonSetup.tsx`, `CommissionerDraft.tsx`, `RosterDraft.tsx`; `tests/Swan.Core.Tests/RosterDraftTests.cs`, `tests/Swan.Services.Tests/SeasonSetupServiceTests.cs`, `tests/Swan.Api.Tests/SeasonEndpointTests.cs`, `src/Swan.Web/src/SeasonSetup.test.tsx`, `src/Swan.Web/e2e/roster-draft.spec.ts`.
- Risks: the current commissioner resolver selects the newest live season, so the new action must check the supplied ID under the same row lock; the current coach read model calls null-deadline drafts “closed,” which needs a presentation change; the existing UI may lose Setup access on activation, so it must refresh access before routing. The database deadline is already nullable; preserve old live/null data and existing rosters.
