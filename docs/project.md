| 2. Admin week workflow, scores import, simulation | In progress. Admin week lifecycle API (`/api/admin/weeks/{weekId}`) is built, and per-game line history is persisted so a line can be added and later approved via `lines/approve-latest`. Admins can record manual game results on a locked week, finalize it, and recompute `WeekScore`s (`/games/{gameId}/result`, `/finalize`, `/recompute`; regular-season weeks only, default scoring settings because none are persisted). `POST /api/admin/seasons/{seasonId}/weeks/recompute` rescores every Final regular-season week of a season on demand (used to correct weeks scored before dog points became Dog-pool-only). A draft week's dog list can be generated from approved lines (`/dog-options/generate`; spread is home-perspective, so +x makes the home team the dog, -x the away team) or replaced by an admin (`PUT /dog-options`). An admin can create one blank Setup season (`POST /api/admin/seasons`, `GET /api/admin/seasons/setup`): PRD default $100 buy-in split Main 60 / Dog 20 / Regular Season 10 / Playoff 10, three double-dog weeks, Sunday 1:00 PM ET deadline; year, name and simulation flag come from the caller and can be revised while the season is in Setup (`PUT /api/admin/seasons/setup`). The buy-in and the four fixed pool stakes can be revised too (`PUT /api/admin/seasons/setup/money`): all USD and positive, stakes must add up to the buy-in, pool names are fixed, and each real change writes a `season.setup.money.updated` audit entry (identical replays write none). Edits take a row lock and run in the retrying execution strategy so they cannot race activation. The weekly team-pick deadline (Eastern `TimeOnly`, JSON `"HH:mm:ss"`, body `{"teamPickDeadlineEastern": "11:30:00"}`) can be revised too (`PUT /api/admin/seasons/setup/deadline`; missing, null or malformed is 400): it returns from `GET /api/admin/seasons/setup`, feeds `LockPolicy.WeekDeadline`, and each real change writes a `season.setup.deadline.updated` audit entry (replays write none). Double-dog weeks were first only an aggregate count (`DoubleDogWeeks`); the wizard now persists the actual week numbers (see the sixth wizard page below). The admin landing page now shows this as a six-page Season setup wizard (start a season, then Basics, Money, Weekly deadline, Teams and point values, Schedule import and Weeks and dogs, each with Back and, except Schedule import before it has an import, Save & continue, saving through its endpoint). The season stores a Setup-only resume step (`SetupStep`: Basics, Money, WeeklyDeadline, TeamsAndPoints, ScheduleImport, WeeksAndDogs, FinesAndPayouts; new and pre-existing seasons open at Basics), returned on the Setup summary and saved with `PUT /api/admin/seasons/setup/step` (`{"step": 1}`; unknown or missing step is 400, replays write no audit, real changes write `season.setup.step.updated`). A successful save records the next page as the resume point without ever moving it backwards. The fourth page, Teams and point values, lists the 32 canonical teams by division (`GET /api/admin/seasons/setup/teams`) and saves a prior-season finish for each (`PUT /api/admin/seasons/setup/teams`, body `{"teams":[{"teamId":…,"finishPosition":1}]}`): exactly the known teams once each, finishes 1 to 4, one team per finish in every division, with the point value derived as the finish (no point-value input). Rows are `SeasonTeam` rows of the Setup season only, replaced as one set under the same row lock, with `season.setup.teams.updated` audited on real changes only; the database enforces one row per (season, team) and per (season, division, finish) (the migration refuses to run if existing rows already break either rule). Saving records Schedule import as the resume point and opens that page. The fifth page, Schedule import, fetches the Setup season's regular-season NFL schedule from BALLDONTLIE on demand (`POST /api/admin/seasons/setup/schedule/preview`; the server reads every cursor page with `seasons[]`, `season_types[]=2` and `per_page=100`, using the key from `ExternalServices:BallDontLie:ApiKey`, a .NET user secret in development, sent only in the `Authorization` header and never returned or logged). A preview saves nothing and lists the games by week with kickoffs shown in Eastern time; the server holds the validated preview in memory for 15 minutes. Confirming (`POST /setup/schedule/import` with the preview's fingerprint) imports exactly that preview without calling the provider again, as regular Weeks 1 to 18 with their Games (each carrying the provider game id, unique across the database) in one transaction under the Setup row lock, and writes a `season.setup.schedule.imported` audit entry recording the provider, season, fetched and imported times, counts and fingerprint (the raw response is not stored). It refuses, changing nothing, when the provider is not configured or has no games, a week is outside 1 to 18 or any of weeks 1 to 18 has no games (a partial schedule is never imported), a provider game id repeats, a team is unknown or not in the season's team list, a kickoff cannot be read, or the season already holds an imported schedule; an unpublished season is a valid empty preview. `GET /setup/schedule` reads only the saved schedule. The manual CSV importer, background refresh, odds/lines/results imports and replacing an imported schedule remain out of scope; The sixth page, Weeks and dogs, reads only the imported schedule (`GET /api/admin/seasons/setup/double-dog-weeks`: all 18 weeks, each with whether it is selected, required or suggested, and reason text; 409 `schedule.missing` until a full schedule is imported) and saves the administrator-confirmed selection (`PUT` the same path, body `{"weeks":[2,12,17]}`): unique regular-season weeks 1 to 18, exactly 3 or 4, always including Week 2 (R7), else 400 `season.double-dogs` with the reason and nothing changed. Week 2 is required; the weeks containing U.S. Thanksgiving (fourth Thursday of November) and December 25, judged by game kickoffs in America/New_York, are only suggested, and may overlap each other or Week 2. The selection is persisted on the season (`DoubleDogWeekNumbers`; existing seasons keep an empty selection, none is invented), `Settings.DoubleDogWeeks` is kept equal to its count, a real change writes a `season.setup.double-dogs.updated` audit entry (replays none) under the same row lock, and `Season.Activate()` now fails unless a valid selection is saved. Saving records Fines and payouts as the resume point (never moving it backwards). Fines and payouts is listed as coming next and is not a page yet. Fine amount, payout splits, double-dog week numbers and playoff settings (the rest of the wizard) remain. Only one Setup season can exist, enforced by a partial unique index (`ux_seasons_single_setup`); the migration refuses to run if duplicate Setup seasons already exist and never deletes or merges them. Scores import and simulation remain. | — |
